# Spec Delta

## Purpose

회의에서 나온 할 일을 대기 · 진행 · 완료 세 칸 칸반으로 보여 주고, 팀원이 상태 · 담당자 · 기한을 고치며 owner 가 빠진 항목을 지우게 하는 기능이다.

## ADDED Requirements

### Requirement: 할 일 보드 보기
<!-- 근거: E-01 · E-02 · E-12 / todos.html -->
보드는 대기 · 진행 · 완료 3열이며 각 카드에 내용 · 회의록 제목 · 담당자 · 기한을 보여야 한다(SHALL). "내 할 일" 은 로그인한 사람에게 배정된 것만, "전체" 는 팀 전체이다. 정렬은 status 다음 due_text 이다.

#### Scenario: 내 할 일
- **WHEN** "내 할 일" 탭을 연다
- **THEN** `GET /api/me/todos` 가 200 으로 내게 배정된 것만 돌려주고 "n / m 완료" 합계가 보인다

#### Scenario: 팀 전체
- **WHEN** "전체" 탭을 연다
- **THEN** `GET /api/teams/{id}/todos` 가 200 으로 팀 전체를 돌려주고 각 줄에 meeting_title 이 있다

#### Scenario: 빈 상태
- **WHEN** 배정된 할 일이 0건이다
- **THEN** 200 + 빈 배열이고 화면은 "배정된 할 일이 없음" 과 "회의록을 올리면 할 일이 자동으로 뽑혀 나옴" 을 보인다

### Requirement: 끌어서 상태 변경
<!-- 근거: E-03 · E-04 / todos.html -->
카드를 끌어 다른 칸에 놓으면 상태가 바뀌어야 한다(SHALL). 구현은 포인터 이벤트로 하며 HTML5 네이티브 드래그는 터치에서 동작하지 않으므로 쓰지 않는다(MUST NOT). 끄는 동안 서버를 부르지 않고 놓는 순간 한 번만 호출하며, 실패하면 카드가 원래 칸으로 돌아간다.

#### Scenario: 끄는 중
- **WHEN** 카드를 집어 끈다
- **THEN** 반투명 사본이 포인터를 따라가고 놓을 칸이 점선으로 바뀌며 "여기에 놓기" 가 보인다

#### Scenario: 놓기
- **WHEN** 다른 칸에 놓는다
- **THEN** `PUT /api/todos/{id}` 가 한 번만 불리고 200 이면 카드가 새 칸에 남으며 "상태를 옮김" 알림이 보인다

#### Scenario: 이동 실패
- **WHEN** 놓은 뒤 서버가 오류를 돌려준다
- **THEN** 카드가 원래 칸으로 돌아간다

### Requirement: 눌러서 칸 고르기
<!-- 근거: E-05 / todos.html -->
좁은 화면에서는 칸이 세로로 쌓여 끌 수 없으므로, 카드를 누르면 대기 · 진행 · 완료 버튼이 떠서 칸을 고를 수 있어야 한다(SHALL). 지금 칸의 버튼은 비활성이다. 상태는 OPEN · DOING · DONE 세 가지뿐이고 되돌림도 허용한다.

#### Scenario: 칸 고르기
- **WHEN** 카드를 끌지 않고 누른다
- **THEN** 카드 아래에 세 칸 버튼이 뜨고 지금 칸은 눌리지 않으며 다른 칸을 누르면 상태가 바뀐다

#### Scenario: 되돌림
- **WHEN** 완료 칸의 카드를 진행 칸으로 옮긴다
- **THEN** 200 이고 상태가 DOING 이 된다

### Requirement: 담당자 배정
<!-- 근거: D-03 · E-06 / todos.html, detail.html -->
팀원 누구나 담당자를 바꿀 수 있어야 한다(SHALL). 칸반에서는 담당자 배지를 눌러 바꾸고 상세에서는 선택 상자로 바꾼다. "미정" 도 하나의 값이다. 배정은 활동 기록에 `todo_assign` 으로 남는다.

#### Scenario: 담당자 바꾸기
- **WHEN** 담당자를 최선임으로 바꾼다
- **THEN** `PUT /api/todos/{id}` 가 200 을 돌려주고 카드의 배지와 활동 기록이 바뀐다

#### Scenario: 담당자 미정
- **WHEN** 회의에서 담당자가 정해지지 않은 할 일이다
- **THEN** 담당자 배지는 "미정" 이며 지어낸 이름이 들어가지 않는다

### Requirement: 기한 입력
<!-- 근거: D-03 · E-06 · E-08 / todos.html, detail.html -->
기한은 자유 글자(due_text)이다. 기한 배지를 누르면 그 자리에 입력칸이 열리고 Enter 나 포커스를 잃을 때 저장해야 한다(SHALL). 상세 화면의 할 일에도 담당자 옆에 같은 기한 칸이 있다. 서버는 기한을 비교하지 않는다.

#### Scenario: 기한 쓰기
- **WHEN** 기한 배지를 누르고 "다음 주 금요일" 을 쓴 뒤 Enter 를 친다
- **THEN** `PUT /api/todos/{id}` 가 200 을 돌려주고 배지에 그 글자가 보인다

#### Scenario: 비움
- **WHEN** 입력칸을 비워 저장한다
- **THEN** 기한은 "미정" 으로 저장된다

### Requirement: 기한 지남 표시
<!-- 근거: E-08 / todos.html -->
기한이 지났는지는 서버가 판정하지 않고 화면이 한다(MUST). 지난 날짜를 가리키는 글자("어제", "지난 주", "지난 달" 과 지난 날짜)이고 완료하지 않은 할 일에만 왼쪽 붉은 띠와 붉은 기한 글자를 쓴다.

#### Scenario: 기한 지남
- **WHEN** 완료하지 않은 할 일의 기한이 "어제" 이다
- **THEN** 카드에 왼쪽 붉은 띠가 있고 기한 글자도 붉다

#### Scenario: 완료한 것은 제외
- **WHEN** 기한이 "지난 주" 이지만 이미 완료했다
- **THEN** 붉은 띠가 없다

### Requirement: 담당자 필터
<!-- 근거: E-07 · E-09 · E-10 / todos.html -->
담당자 필터는 화면에서 거르며 서버를 다시 부르지 않아야 한다(SHALL). "미정" 도 필터 값이다. 완료한 할 일도 지우지 않고 남겨 활동 기록의 근거가 된다.

#### Scenario: 박과장만 보기
- **WHEN** 필터에서 "박과장" 을 고른다
- **THEN** 서버 호출 없이 그 담당자의 카드만 보인다

#### Scenario: 담당자 미정만 보기
- **WHEN** 필터에서 "미정" 을 고른다
- **THEN** 담당자가 정해지지 않은 카드만 보인다

### Requirement: 할 일 삭제
<!-- 근거: E-11 / todos.html -->
할 일 삭제는 owner 만 할 수 있어야 한다(SHALL). member 가 부르면 403 `OWNER_ONLY` 를 돌려준다. 화면은 응답의 `can_delete` 가 false 이면 "삭제" 버튼을 흐리게 하고 누를 수 없게 한다.

#### Scenario: owner 가 삭제
- **WHEN** owner 가 "삭제" 를 누른다
- **THEN** `DELETE /api/todos/{id}` 가 204 를 돌려주고 카드가 사라진다

#### Scenario: member 가 삭제 시도
- **WHEN** member 가 카드를 본다
- **THEN** `can_delete` 가 false 이고 "삭제" 는 흐리며 눌러도 동작하지 않는다
